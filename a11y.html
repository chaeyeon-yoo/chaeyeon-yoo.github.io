SK텔레콤 T world
PERIOD

OVERVIEW

운영 환경에서 발견한 접근성 이슈를
구조적으로 개선했습니다.

SK텔레콤 T world 운영 과정에서 웹 접근성(WA) 인증 갱신 업무를 담당했습니다. 단순 체크리스트 대응이 아닌, 실제 사용자 시나리오 기반으로 이슈를 발견하고 HTML 구조와 ARIA 속성을 개선하는 방식으로 접근했습니다.

아래는 실무에서 직접 수정하거나 검토한 마크업 개선 사례 중 10건을 선별해 정리했습니다. 웹 접근성(WA) 인증 심사 기준에 따라 개선했으며, 개선 전후를 코드 단위로 기록했습니다.

10+ 실무 개선 경험
5회 WA 인증 갱신
Level A WCAG 기준 대응

CASE 01

이미지 대체 텍스트 — WCAG 1.1.1 / Level A

의미 있는 이미지에 alt 속성이 없거나,
파일명이 그대로 노출되고 있었습니다.

BEFORE 
    <!-- alt 없음 -->
    <img src="banner_main.jpg">

    <!-- 의미 없는 alt -->
    <img src="event.jpg"
        alt="이미지">

    <!-- 장식용인데 alt 없음 -->
    <img src="divider.png">
AFTER 
    <!-- 이미지 내용을 구체적으로 설명 -->
    <img src="banner_main.jpg"
        alt="5G 요금제 여름 특가, 최대 50% 할인">

    <!-- 맥락에 맞는 구체적 alt -->
    <img src="event.jpg"
        alt="7월 한정 요금제 출시 이벤트">

    <!-- 장식용은 alt="" 빈 값 처리 -->
    <img src="divider.png"
        alt="">

스크린리더는 alt 값을 그대로 읽습니다. alt가 없으면 파일명을 읽거나 건너뛰어 정보가 누락되고, "이미지"처럼 의미 없는 값은 정보를 전달하지 못합니다. 의미 있는 이미지는 내용을 설명하고, 장식용은 alt=""로 처리해 스크린리더가 건너뛰게 해야 합니다. 같은 패턴의 이미지 마크업은 이후 작업에서도 셀프 점검 항목으로 관리했습니다.

CASE 02

버튼 레이블 및 type 속성 — WCAG 4.1.2 / Level A

아이콘 버튼에 레이블이 없고,
type 누락으로 의도치 않은 submit이 발생했습니다.

BEFORE 
    <!-- type 없음 + 레이블 없는 아이콘 버튼 -->
    <button class="btn-close">
      <img src="icon-close.svg" alt="">
    </button>

    <!-- 맥락 없는 "더보기" 반복 -->
    <button>더보기</button>
    <button>더보기</button>
AFTER 
    <!-- type + aria-label 명시 -->
    <button type="button"
            class="btn-close"
            aria-label="팝업 닫기">
      <img src="icon-close.svg" alt="">
    </button>

    <!-- 맥락을 담은 aria-label -->
    <button type="button"
            aria-label="5G 요금제 더보기">
      더보기
    </button>
    <button type="button"
            aria-label="인터넷 요금제 더보기">
      더보기
    </button>

type="button"을 명시하지 않으면 폼 내부에서 submit으로 동작할 수 있습니다. 아이콘만 있는 버튼은 스크린리더가 기능을 읽지 못하므로 aria-label로 목적을 명확히 전달해야 합니다. "더보기"가 반복될 때도 각각 aria-label로 맥락을 구분해줘야 합니다.

CASE 03

키보드 내비게이션 — WCAG 2.1.1 / Level A

모달이 열릴 때 포커스가 이동되지 않아
키보드 사용자가 모달을 사용할 수 없었습니다.

BEFORE 
    <!-- 포커스 이동 없음 -->
    <div class="modal" id="modal">
      모달 내용
      <button>닫기</button>
    </div>

    <script>
    function openModal() {
      document.getElementById('modal')
        .style.display = 'block';
    }
    </script>
AFTER 
    <!-- role + aria 속성 + 포커스 이동 -->
    <div class="modal" id="modal"
        role="dialog"
        aria-modal="true"
        aria-labelledby="modal-title">
      <h2 id="modal-title"
          tabindex="-1">제목</h2>
      <button type="button"
              aria-label="모달 닫기">닫기</button>
    </div>

    <script>
    function openModal() {
      const modal = document.getElementById('modal');
      modal.style.display = 'block';
      modal.querySelector('#modal-title').focus();
    }
    </script>

모달이 열릴 때 포커스가 이동되지 않으면 키보드 사용자는 모달 뒤 배경 콘텐츠를 계속 탐색하게 됩니다. role="dialog"와 aria-modal="true"로 보조 기술에 모달임을 알리고, 열릴 때 포커스를 내부로 이동시켜야 합니다.

CASE 04

폼 레이블 연결 — WCAG 1.3.1 / Level A

입력 필드와 레이블이 연결되지 않아
스크린리더가 어떤 필드인지 안내하지 못했습니다.

BEFORE 
    <!-- span으로 레이블 처리 -->
    <div class="form-group">
      <span class="label">이름</span>
      <input type="text"
            placeholder="이름을 입력하세요">
    </div>

    <!-- placeholder만 있고 label 없음 -->
    <input type="email"
          placeholder="이메일 주소">
AFTER 
    <!-- for-id로 label과 input 연결 -->
    <div class="form-group">
      <label for="input-name">이름</label>
      <input type="text"
            id="input-name"
            placeholder="홍길동">
    </div>

    <!-- label + placeholder 함께 제공 -->
    <label for="input-email">이메일</label>
    <input type="email"
          id="input-email"
          placeholder="example@email.com">

placeholder는 입력하면 사라지기 때문에 레이블을 대체할 수 없습니다. label for와 input id를 연결하면 스크린리더가 필드 진입 시 레이블을 읽어주고, 레이블 클릭 시 해당 필드로 포커스가 이동합니다. 레이아웃 구조는 유지한 채 label 요소와 for/id 연결로 해결했습니다.

CASE 05

숨김 텍스트 — WCAG 1.3.1 / Level A

display:none으로 처리한 텍스트는
스크린리더에서도 읽히지 않았습니다.

BEFORE 
    <style>
      .hidden { display: none; }
    </style>

    <!-- 스크린리더도 못 읽음 -->
    <a href="/cart">
      <img src="icon-cart.svg" alt="">
      <span class="hidden">장바구니</span>
    </a>
AFTER 
    <style>
      .visually-hidden {
        position: absolute;
        width: 1px; height: 1px;
        padding: 0; margin: -1px;
        overflow: hidden;
        clip: rect(0,0,0,0);
        white-space: nowrap;
        border: 0;
      }
    </style>

    <!-- 화면엔 숨기고 보조기술엔 전달 -->
    <a href="/cart">
      <img src="icon-cart.svg" alt="">
      <span class="visually-hidden">장바구니</span>
    </a>

display:none은 스크린리더에서도 콘텐츠를 숨깁니다. visually-hidden은 시각적으로 보이지 않지만 DOM에 존재해 보조 기술이 읽을 수 있습니다. 아이콘 링크, 건너뛰기 링크 등에 필수로 사용합니다.

CASE 06

툴팁 — WCAG 2.1.1 / Level A

hover로만 표시되는 툴팁은
키보드 사용자에게 전달되지 않았습니다.

BEFORE 
    <!-- hover CSS만으로 툴팁 처리 -->
    <div class="tooltip-wrap">
      <button type="button">?</button>
      <span class="tooltip">
        요금제 상세 안내입니다.
      </span>
    </div>

    <style>
      .tooltip { display: none; }
      .tooltip-wrap:hover .tooltip {
        display: block;
      }
    </style>
AFTER 
    <!-- aria-describedby + role="tooltip" -->
    <div class="tooltip-wrap">
      <button type="button"
              aria-label="요금제 안내"
              aria-describedby="tooltip-plan">
        ?
      </button>
      <span id="tooltip-plan"
            role="tooltip">
        요금제 상세 안내입니다.
      </span>
    </div>

    <style>
      /* hover + focus-within 모두 대응 */
      .tooltip-wrap:hover .tooltip,
      .tooltip-wrap:focus-within .tooltip {
        display: block;
      }
    </style>

hover로만 표시되는 툴팁은 키보드 포커스 시에도 표시되어야 합니다. aria-describedby로 버튼과 툴팁을 연결하면 스크린리더가 버튼 포커스 시 툴팁 내용을 함께 읽어줍니다.

CASE 07

탭 UI — WCAG 4.1.2 / Level A

div와 button만으로 구현된 탭은
스크린리더가 탭 구조임을 인식하지 못했습니다.

BEFORE 
    <!-- div/button만으로 탭 구현 -->
    <div class="tab-list">
      <button class="tab active">
        5G 요금제
      </button>
      <button class="tab">
        LTE 요금제
      </button>
    </div>
    <div class="tab-panel">
      5G 요금제 내용
    </div>
AFTER 
    <!-- ARIA role로 탭 구조 명시 -->
    <div role="tablist"
        aria-label="요금제 종류">
      <button type="button"
              role="tab"
              aria-selected="true"
              aria-controls="panel-5g">
        5G 요금제
      </button>
      <button type="button"
              role="tab"
              aria-selected="false"
              aria-controls="panel-lte">
        LTE 요금제
      </button>
    </div>
    <div id="panel-5g"
        role="tabpanel">
      5G 요금제 내용
    </div>

role="tablist/tab/tabpanel"을 함께 사용하면 스크린리더가 "탭 1/2, 선택됨"과 같이 구조를 안내합니다. aria-selected로 현재 선택된 탭을, aria-controls로 연결된 패널을 명시합니다.

CASE 08

아코디언 — WCAG 4.1.2 / Level A

아코디언 열림/닫힘 상태가 시각적으로만 표현되어
스크린리더 사용자는 현재 상태를 알 수 없었습니다.

BEFORE 
    <!-- 열림/닫힘 상태 전달 없음 -->
    <div class="accordion">
      <button type="button"
              class="accordion-btn">
        자주 묻는 질문
      </button>
      <div class="accordion-panel">
        답변 내용
      </div>
    </div>
AFTER 
    <!-- aria-expanded + aria-controls -->
    <div class="accordion">
      <button type="button"
              class="accordion-btn"
              aria-expanded="false"
              aria-controls="faq-panel-1">
        자주 묻는 질문
      </button>
      <div id="faq-panel-1" hidden>
        답변 내용
      </div>
    </div>

    <!-- JS: 클릭 시 상태 토글 -->
    btn.setAttribute('aria-expanded', 'true');
    panel.removeAttribute('hidden');

aria-expanded="false/true"로 열림/닫힘 상태를 보조 기술에 전달합니다. 패널은 hidden 속성으로 제어하면 스크린리더도 닫힌 상태에서는 내용을 읽지 않습니다.

CASE 09

테이블 접근성 — WCAG 1.3.1 / Level A

caption, scope, thead가 없어
스크린리더가 셀과 헤더의 관계를 파악하지 못했습니다.

BEFORE 
    <!-- caption, scope, thead 없음 -->
    <table>
      <tr>
        <td>요금제명</td>
        <td>월정액</td>
        <td>데이터</td>
      </tr>
      <tr>
        <td>5G 베이직</td>
        <td>55,000원</td>
        <td>10GB</td>
      </tr>
    </table>
AFTER 
    <!-- caption + thead + scope 적용 -->
    <table>
      <caption>5G 요금제 비교표</caption>
      <thead>
        <tr>
          <th scope="col">요금제명</th>
          <th scope="col">월정액</th>
          <th scope="col">데이터</th>
        </tr>
      </thead>
      <tbody>
        <tr>
          <td>5G 베이직</td>
          <td>55,000원</td>
          <td>10GB</td>
        </tr>
      </tbody>
    </table>

caption은 테이블 제목을 스크린리더에 전달하고, scope="col/row"는 헤더 셀이 어느 방향의 데이터를 설명하는지 명시합니다. thead/tbody 구분으로 구조도 명확해집니다. 테이블 마크업 작업 시에는 caption/scope를 빠짐없이 넣어 작업했습니다.

CASE 10

팝업 vs 페이지 이동 링크 구분 — WCAG 4.1.2 / Level A

새 창 링크와 팝업, 페이지 이동이 동일한 형태로
사용자가 컨텍스트 전환을 예측할 수 없었습니다.

BEFORE 
    <!-- 새 창 안내 없음 -->
    <a href="https://external.com"
      target="_blank">
      요금제 안내 바로가기
    </a>

    <!-- 팝업과 페이지 이동이 같은 형태 -->
    <a href="#"
      onclick="openPopup()">
      자세히 보기
    </a>
    <a href="#section-plan">
      자세히 보기
    </a>
AFTER 
    <!-- 새 창: title 속성으로 안내 -->
    <a href="https://external.com"
      target="_blank"
      title="요금제 안내 바로가기 (새 창으로 열림)">
      요금제 안내 바로가기
    </a>

    <!-- 팝업: button으로 명확히 구분 -->
    <button type="button"
            aria-haspopup="dialog">
      팝업으로 자세히 보기
    </button>

    <!-- 페이지 이동: 앵커 id 연결 -->
    <a href="#section-plan">
      요금제 자세히 보기
    </a>

페이지 이동은 a href, 팝업 호출은 button으로 구분하는 것이 원칙입니다. 새 창은 title 속성으로 사전 안내하고, aria-haspopup="dialog"로 팝업 호출임을 명시합니다.
